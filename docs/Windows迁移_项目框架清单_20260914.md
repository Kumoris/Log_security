## 4. Windows 运行环境

### 推荐使用 WSL2

已在本地源码确认 runner.py 与 rerun_affected.py 使用 signal.SIGALRM / signal.alarm；Python 官方标注 alarm 为 Unix 功能。Git 调用还使用 /dev/null。这套当前脚本不宜直接在原生 Windows Python 下全量运行。[Python 官方说明](https://docs.python.org/3/library/signal.html#signal.alarm)

Windows 11，或符合官方要求的 Windows 10，可在管理员 PowerShell 中安装 WSL，然后进入 Linux 环境。以下为目标机器上的操作说明，本次未执行：

```powershell
wsl --install
wsl -l -v
```

按提示完成重启与 Linux 用户初始化，并确认发行版运行于 WSL2。[微软安装说明](https://learn.microsoft.com/en-us/windows/wsl/install)

把实验文件放在 WSL Linux 文件系统中。大量小文件、Git 对象和 SQLite 更适合在该文件系统内工作；不要把运行位置默认设为 /mnt/c 下。[微软文件系统建议](https://learn.microsoft.com/en-us/windows/wsl/filesystems)

### Python 与依赖

本机实际解释器是外部 agent_log_privacy/.venv/bin/python，版本 3.11.15。pyproject.toml 声明 Python >=3.11；为减少迁移差异，优先重建 Python 3.11 环境并记录完整版本。

macOS 的 .venv 不能作为 Windows/WSL 的可运行环境直接搬用。新机重建成功后，当前这条研究流程可使用 agentlog_unified 自己的 .venv，不必依赖旧 agent_log_privacy 的虚拟环境。

本机已核对：PyDriller 2.11、PyYAML 6.0.2、jsonschema 4.23.0、Pygments 2.21.0、tree-sitter 0.25.2、JavaScript grammar 0.25.0、TypeScript grammar 0.23.2、Go grammar 0.25.0、Java grammar 0.23.5、pytest 8.3.5、pyarrow 21.0.0、setuptools 75.8.0、wheel 0.45.1。

在 WSL 中先准备 Git 和 Python 3.11（含 venv），进入迁移后的 agentlog_unified，再运行：

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install --no-deps --no-build-isolation -e .
.venv/bin/python -m pip check
.venv/bin/python -m agentlog_unified --help
```

需读取原始 Parquet 时，再安装 requirements-aidev.lock。不要直接使用工作区最外层的 requirements.txt 代替本包锁定文件。

锁定包在目标 Linux/Python 平台的下载和安装尚未测试；失败时记录包名、版本和报错，不静默放宽锁定版本。若必须变更依赖，使用新的环境记录和分析身份。

Go、Node、Java、Docker 等属于进一步核验目标仓库构建时的按项目依赖，并非读取已有字段表都要安装。它们应按指定历史源码的构建文件准备，不能用“环境安装成功”代替目标构建通过。

## 5. 必须处理的绝对路径问题

当前旧根路径为：

```text
/Users/lzh/Downloads/Log 研究/agentlog_unified
```

已确认路径存在于 current_run.json、current_rerun.json、input_manifest.json、源码覆盖记录、local_evidence_file、cache_path，以及 sources.sqlite 内保存的 JSON。程序会直接用 Path(...) 打开这些路径；仅把目录复制到 D 盘不会自动修复引用。

此外，rerun_affected.py 的分析身份计算把分析组件的绝对路径作为哈希字典的键。即使代码字节未变，搬到另一个真实路径也可能改变分析身份，不能手工把它伪装成原运行。

可选两条迁移路线：

1. **先兼容现有冻结实验：**在 WSL 的 Linux 文件系统中使用同样的真实根路径 /Users/lzh/Downloads/Log 研究/agentlog_unified。Linux 可以使用这样的目录名称。它需要在新机创建并授予当前 Linux 用户写权限，本次没有执行。这能减少已确认的绝对路径变化，但仍需核验外部引用和环境差异；不能保证所有历史实验即刻可运行。不要仅用指向另一目录的符号链接冒充同路径，因为源码使用 Path.resolve()，解析后仍可能改变身份。
2. **长期改用新路径：**例如 /home/<Linux用户名>/projects/agentlog_unified。需要单独实现路径映射或迁移适配，覆盖 JSON/JSONL/CSV/SQLite 中用于打开文件的路径。保留原冻结材料和原路径，适配结果写入独立副本并记录映射、原哈希及新哈希。源码或签名材料变化后使用新运行身份，不在原材料中全局搜索替换。

freeze.py 还保留了一个指向本机 Codex 附件的初始请求路径；已冻结请求在字段提取目录的 inputs/ 中。接续现有实验不应重跑 freeze.py；若另起数据冻结，需要显式提供新的请求来源。

## 6. 迁移与验收顺序

1. 选择一个主任务停止写入后的时点，冻结目录副本，记录当前指针、依赖版本和文件清单。不要边生成实验结果边复制数据库。
2. 首次建议完整迁移约 45 GB 的 agentlog_unified。目标机同时保存归档和解压目录时，两份空间都要计入，再给虚拟环境及新实验留余量；可按至少 100 GB 空闲空间规划，实际压缩率未测。
3. 可以不带 .DS_Store、__pycache__/、*.pyc、.pytest_cache/。这些排除规则不能扩展到 source_blobs/、evidence/、cache/ 或各类 SQLite。
4. 保留 Git 缓存中的隐藏文件和对象目录。打包与解压保持字节、大小写及目录层级；不要通过编辑器批量转换换行符。SQLite 若存在 WAL/SHM，不能随意删除或仅复制主文件；应在无写入的冻结时点复制一致集合，或使用一致性备份。
5. 传输前后校验归档 SHA-256；这只证明归档传输一致。解压后再核对冻结文件清单，以及已有输入、分析组件和源文件哈希。建议对迁移副本检查符号链接和 Git alternates 等外部依赖；本次没有完成全目录依赖闭包扫描。
6. 在 WSL 重建依赖，先做 pip check、CLI --help，再运行下面的合成测试。测试成功只说明相应提取规则在新环境可运行，不代表历史证据路径全部有效。
7. 只读核验指针、JSONL/CSV、SQLite 与源码证据能打开，CSV 使用标准解析器，嵌入 JSON 单独解析，不按物理行数数案例。选已知 49 条和新 150 条中的少量冻结案例，在独立输出中回放并与原字段/锚点/状态比较。
8. 小批次差异解释清楚后，才推进受影响部分或全量。原始审查字段、未知/受阻、不同证据层和同源关联均保留；不要因迁移把它们重置为安全或已验证。
