# 分类规则 1.2.0

本版目录仍为 49 个细类；改进已有类型的字段识别，不增加真实敏感数据类型的声明。包版本为 0.5.0，正文检测器为 1.2.0，JSON 结构检测器为 1.1.0。

字段规范化由日志、正文、JSON 键和具名凭证脱敏共同使用。缩写边界统一为 snake_case；聚合字段继续排除。对于 `APIKey.id` 等字段投影，只检查最终字段及必要的直接父名称，匹配必须涉及最终字段，避免把父对象的类型错误传播给子字段。此处是静态字段提示，不解析任意调用的返回值。

JSON 解析器新增有限的直接父键上下文。例如 `{"user":{"id":11}}` 可产生 `QID.user_identifier` 提示，依据单列为 `json_parent_key_hint`。只有既有受控歧义字段允许借用直接父键，数组元素、再解码和中间对象边界不会自动继承祖先含义。空值、引用、载体、示例及未知节点仍按原质量边界处理。

实际依据是对旧版无解析缺口文档的回读：16 个原未识别的节点×类型位置获得有限上下文支持。它们仍为低置信命名提示，`human_review_status=pending`、`runtime_confirmed=false`。另 30 个任意拼接线索中，25 个被拒绝，5 个仍未决；不能把这 5 个称为已确认有效增量。[固定证据回放](aidev_structured_parent_context_v050_replay.json)

对 5,422 份可回放顶层 JSON 文档（含 35 份存在内层缺口的 `partial` 文档）的另一项探查中，98 个预设别名没有带来新增候选，保留零结果。父上下文探查只选其中 5,387 份无解析缺口文档；两者分母不同。它们不覆盖所有未解析正文，不证明没有其他类型或别名。[JSON 别名探查](json_key_alias_probe_v050.json)

随后对全部 105 个字符串列做固定别名探查，发现 28 处赋值写法、19 个单元格。有限回读的 14 处中，12 处所在单元格已被旧规则赋予相应类型，剩余 2 处是未决的环境变量标记语法。保留待审发现，本版未据此加入别名规则。[全字符串探查与边界](alias_discovery_v050_summary.md)

版本变化会改变运行指纹。保留旧输出，使用新运行目录；`--resume` 仅恢复与原运行相同的实现及输入。旧来源中的 `not_evaluated` 与空计数保持不变，不能按新版本倒填为零。

具名脱敏复用 AUTH 和邮箱字段提示，补上缩写键的等价识别；其他字段仍沿用既有脱敏范围。它不能保证任意未知字段中嵌入的秘密均被识别。
